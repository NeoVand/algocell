# Stage H (well-mixed control of Stage G, L = 16) — exact commands

Pre-registration: PLAN.md, entry "2026-10-08 night (Stage H pre-registration: does space sustain the open phase?)".
Conditions: `conds/stageH.json` (10 worlds, label `mixed@closure`, `grid: mixed`, seeds 3001–3010, every other field identical
to the Stage G L = 16 conditions; generated by `make_conds.stage_h()`). Control: Stage G L = 16 (`results/stageG/`, 20 worlds).
All commands run from `experiments/` with `.venv/bin/python`; nothing here touches `runs/stageG/` or `results/stageG/`.

## How the Stage G files were produced (for reference)

`./analyze_stage.sh stageG` (after `./fetch.sh stageG` from the Modal volume) ran, in this order:

| command | output |
|---|---|
| `.venv/bin/python assay_batch.py runs/stageG > runs/stageG_assay.log 2>&1` | `runs/stageG/analysis/assays.csv` — the per-run assays (t_rep, t_faith, trep_*, final_*, final_func_*) |
| `.venv/bin/python succession.py runs/stageG` | `analysis/succession.csv`, `succession_cells.csv` |
| `.venv/bin/python zoo.py runs/stageG` | `analysis/zoo.csv`, `ZOO.md` |
| `.venv/bin/python analyze.py runs/stageG` | `analysis/runs.csv`, `cells.csv`, `km_L*.{pdf,svg,png}` |
| `.venv/bin/python findings.py runs/stageG --out runs/stageG/analysis/NUMBERS.md` | `analysis/NUMBERS.md` |
| `.venv/bin/python report.py runs/stageG --out runs/REPORT_stageG.md` | `runs/REPORT_stageG.md` |
| `./publish_results.sh stageG` | copies `runs/stageG/analysis/{*.csv,*.png,*.pdf,*.svg,ZOO.md,NUMBERS.md}` and every sub-directory into `results/stageG/` |

then, separately (logs `runs/stageG_c4.log`, `runs/stageG_stage_g.log`, `runs/stageG_stage_g2.log`):

| command | output |
|---|---|
| `.venv/bin/python c4_functional.py runs/stageG > runs/stageG_c4.log 2>&1` | `runs/stageG/analysis/c4/functional.csv` (one row per run × sampled step: heritable / faithful fraction of the 16 random cells), `functional_fixed_steps.csv`, `NUMBERS_C4.md`, `C4_functional_st128_k4.*` |
| `.venv/bin/python stage_g.py --dir runs/stageG > runs/stageG_stage_g.log 2>&1` | `runs/stageG/analysis/stageG/stage_g_runs.csv` (per world: first/final tape, control flow, block-repeat, partner test `copied`/`damaged`), `NUMBERS_G.md`, `G_partner_independence.*`, `G_heritable_fraction.*` |
| `./publish_results.sh stageG` (again) | `results/stageG/c4/`, `results/stageG/stageG/` (byte-identical copies of `runs/stageG/analysis/c4/`, `.../stageG/`) |

## 0. Before the launch (local GPU only; no paid compute)

```sh
.venv/bin/python -m algocell_exp.gen_mixed_shader --check     # algocell_exp/shader/sim_mixed_L16.wgsl is the square shader with one line changed
.venv/bin/python -m pytest tests -q                             # 70 tests, incl. tests/test_mixed.py (pairing statistics, smoke run, condition file)
.venv/bin/python make_conds.py stageH                           # only if make_conds.py changed; conds/stageH.json must equal the generator (tested)
```

The dry run that preceded the launch (one world, horizon 1,000, `runs/stageH_dry/`, log `runs/stageH_dry.log`):

```sh
.venv/bin/python stage_h_local.py --only 1 --horizon 1000 --out runs/stageH_dry
```

`stage_h_local.py` refuses a `--horizon` override into the default `runs/stageH`, so truncated runs can never sit next to the real files.

## 1. The runs (sequential on the local GPU; resumable)

```sh
.venv/bin/python stage_h_local.py > runs/stageH_launch.log 2>&1
```

Produces, per world, `runs/stageH/mixed@closure_L16_st128_k4_s30NN.jsonl` (condition record, 698 samples, summary line),
`.summary.json` (written last, atomically; records `grid: "mixed"` and `provenance.shader_file = sim_mixed_L16.wgsl`,
`provenance.stage = "H"`, `purpose = "well-mixed control"`, git commit, condition-file hash, launch time),
`.soup_emergence.u8.br` (first tq_10 crossing), `.soup_final.u8.br`, and `.soup_t{500,1000,2000,3000,5000,7500,10000,15000,20000,30000,50000,75000,100000,150000,200000,300000}.u8.br`
with an interaction census in the sample of each snapshot step. `batch.check_outputs` runs on every world (schedule, snapshots,
census, parameter echo incl. grid); problems are printed and make the exit status non-zero. A world whose summary exists is
skipped, so after an interruption re-run the same command. Measured on the Apple M4 (dry run): 0.56 ms per step on the GPU
plus ≈ 25 ms per sample → ≈ 3 min per world, ≈ 30 min for all ten (upper bound 1.3 h at the dry run's 50-step sampling rate).

## 2. Per-run assays → `runs/stageH/analysis/assays.csv`

```sh
.venv/bin/python assay_batch.py runs/stageH > runs/stageH_assay.log 2>&1
```

`select_summaries` restricts the pooled files to the stems of `conds/stageH.json` automatically (the directory's basename), so
nothing but the ten Stage H worlds can enter. Columns used by the Stage H scoring: `t_rep`, `trep_tape`, `trep_mechs`, `t_faith`,
`final_tape`, `final_faithful`, `final_func_rnd`.

## 3. Heritable fraction per sampled step → `runs/stageH/analysis/c4/functional.csv`

```sh
.venv/bin/python c4_functional.py runs/stageH > runs/stageH_c4.log 2>&1
```

One row per world × sampled step in `c4_functional.STEPS` (50 … 300000): `frac_heritable`, `frac_faithful`, `gen2_mean`,
`zero_frac`, `q_share`. Also `functional_fixed_steps.csv`, `NUMBERS_C4.md`, `C4_functional_st128_k4.{pdf,svg,png}` (the mixed arm
draws in the default grey: `figstyle.COLOR` has no entry for `mixed`, deliberately — it is not an ablation).

## 4. Per-world first/final tapes, control flow, partner test → `runs/stageH/analysis/stageH/stage_g_runs.csv`

```sh
.venv/bin/python stage_g.py --dir runs/stageH --out runs/stageH/analysis/stageH --no-verdicts > runs/stageH_stage_g.log 2>&1
```

Same per-world table as Stage G's (`first_tape`, `first_cf`, `first_copied`, `first_damaged`, `final_*`, `t_rep`, `t_faith`),
`NUMBERS_G.md` (per-L numbers and the heritable-fraction medians by step), `G_partner_independence.*`, `G_heritable_fraction.*`.
`--no-verdicts` (added for Stage H; default behaviour unchanged) skips the Stage G verdict block, whose thresholds are
pre-registered for 20 worlds per L and would be mis-scored on 10.

## 5. The standard stage chain (CPU) and publication

```sh
.venv/bin/python succession.py runs/stageH > runs/stageH_succession.log 2>&1
.venv/bin/python zoo.py runs/stageH > runs/stageH_zoo.log 2>&1

.venv/bin/python report.py runs/stageH --out runs/REPORT_stageH.md > runs/stageH_report.log 2>&1
./publish_results.sh stageH
```

(`./analyze_stage.sh stageH --no-fetch` runs steps 2 and 5 in one go, without the Modal download.) `publish_results.sh` copies
`runs/stageH/analysis/*` and the sub-directories `c4/` and `stageH/` into `results/stageH/` and `runs/REPORT_stageH.md` into
`results/REPORT_stageH.md`; this file (`COMMANDS.md`) is hand-written and is kept.

## 6. Stage H scoring (H0–H2 against Stage G L = 16) — NOT YET WRITTEN

Inputs are complete after steps 2–4. Per PLAN.md: per world, `t_rep` and the first heritable tape (`assays.csv`:
`t_rep`, `trep_tape`; pusher = `01 c5` or a register variant, cf. `zoo.csv`); `h_open` = median `frac_heritable` over sampled steps
2,000–20,000 and `t_close70` = first sampled step with `frac_heritable ≥ 0.7` (`c4/functional.csv`). Baselines from
`results/stageG/c4/functional.csv` and `results/stageG/stageG/stage_g_runs.csv` (tape_len 16): t_rep median 525, h_open median
0.125, t_close70 median 30,000 (20/20). Tests: H0 pusher first in ≥ 7/10 with t_rep in 100–5,000; H1 h_open mixed median < 0.125,
one-sided Mann–Whitney 10 vs 20, P < 0.05 (kill: median ≥ 0.125 with P ≥ 0.2); H2 t_close70 mixed median < 30,000, P < 0.05
(kill: ≥ 30,000 with P ≥ 0.2); strong form if ≥ 4/10 worlds have no heritable replicator by 300,000. scipy is not installed:
the Mann–Whitney P must be computed in the script (exact for 10 vs 20 or normal approximation with tie correction).
