- Zilion: `@neovand/zilion` 0.3.0-dev, commit `183ff5c7429403439c664487980a40bf62f49b7b` (branch `next`)
- Manifest schema: `zilion.manifest/2`
- Core SHA-256 = `manifest.sha256.core` (the core text as emitted, with its hooks); world SHA-256 = canonical JSON
  of the world spec; WGSL SHA-256 = the whole generated shader (checked against the file by `zmachine.load_machine`).
- `Z80_CORE_WGSL` (the 0.2.0 Z80 core text, byte-identical to the v0.2.0 tag by zilion's `npm run check:bytes`):
  SHA-256 `8db4015dab560cd075b2f4da7de78b6cc5e2b120034bfbf62590eb49784b2955`. A Z80 machine with no hooks emits exactly this text (none in this file);
  the others insert the hook calls at zilion's fixed insertion points.
- Compat: every Z80 machine states its compat (the exporter refuses a Z80 world without one). `'0.2'` is the
  semantics of the 0.2.0 core that all published Algocell results ran on: its frozen generator emits the 0.2.0 core text
  (the core SHA-256 below), and "Core" then reads 0.2.0. `'0.3'` (the fixed core, variant classic or zilog-nmos) appears
  only in the impact study's comparison machines (`imp_*_c1`, `imp_*_c2`, worlds_impact.json), never for registered results.
- The `m6502_*` machines run Zilion's full NMOS 6502 core (status experimental: all 2,560,000 SingleStepTests
  `6502/v1` vectors pass with no divergence rules); `m6502_pair_L16` (worlds.json) is ZSoup's plumbing machine, the
  others (worlds_6502.json) are the 6502 study's census and pilot worlds. A skeleton core (`status: skeleton`) is
  never used for results.
